# GridEngine — оценка готовности к v1.0

Проверка рабочей копии: 2026-10-08. Это инвентаризация реализованного кода, а не подтверждение готовности продукта. Команда сборки была предпринята в отдельной папке `.tmp/vecta_build`, но не запустилась: в окружении PowerShell команда `cmake` не найдена. Следовательно, тесты и компилятор не запускались, исполняемый файл не собран.

## Подтверждено исходниками

| Область | Сейчас | Что нужно до стабильного релиза |
|---|---|---|
| C++ ядро / lifecycle | Есть библиотека C++20 и базовый Engine lifecycle | Контракты ошибок, стабильный API, проверка lifecycle/ресурсов и CI на целевых ОС |
| Проекты | Есть создание/открытие project descriptor | Валидация, миграции форматов, реальные project settings и тестирование повреждённых проектов |
| Scene / Entity | Иерархия, Transform2D, Motion2D, опциональные Sprite/Camera/Collider, сохранение | Компонентная система пока фиксирована полями Entity; сериализация/миграции, ресурсы, границы transform-иерархии и редакторская интеграция требуют доведения |
| Физика | Простое обновление движения и AABB overlap-запросы | Нет разрешения столкновений, импульсов, тел/слоёв/масок и полноценного physics runtime. Нужны спецификация и тесты поведения |
| TileMap | Фиксированная сетка и сохранение | Нет редактора атласа/палитры, слоёв, ввода мышью, undo/redo, сцено-интеграции и визуализации |
| Audio | Конфигурация AudioSource и логические handle-состояния | Реального декодирования и звукового устройства нет; выбрать и интегрировать backend, управлять ресурсами/жизненным циклом, тестировать на ОС |
| Particles | Детерминированный CPU emitter/state update | Нет рендеринга, scene integration, editor controls и профилирования |
| Grid scripting | Числовой прототип; ограниченная привязка к позициям сущности | Нет компонентного API, событий, ввода, физики, отладки/sandbox и runtime lifecycle. Не эквивалентен GDScript/C#/C++ embedding |
| Export | Копирование descriptor/assets/scenes и build metadata | Сам README подтверждает `binary_included=false`: не компилирует игру, не создаёт executable. Нужны runtime/game target, ресурсы, toolchain и реальные Windows/Linux package tests |
| UI / editor | `gridengine_demo` — текстовый CLI-прототип | SDL/ImGui и графического редактора нет; нет инспектора, asset browser, сцено-редактора и play mode |
| Animation | В исходниках нет отдельной системы | Спроектировать и реализовать, интегрировать в Scene/ресурсы/редактор |
| Input / events | В проверенном API не обнаружены | Нужны платформенный input, события и проверяемые контракты |
| Документация / тесты | Есть smoke и тематические тесты согласно CMakeLists | Полнота тестов и сборка не подтверждены; нужны clean CI builds, регрессии, совместимость проектов и документация пользователя |

## Решение по версии

Текущий CMake-проект объявляет версию `0.5.0`, README описывает export-срез v0.9 с явным отсутствием игрового бинарника, а CLI — текстовая демонстрация. На основании доступных файлов называть это v1.0 нельзя. Не следует менять версию на 1.0 или представлять экспорт пакета данных как собранную игру.

## Практический порядок работ

1. Восстановить доступную среду CMake и C++20-компилятор, получить чистую сборку и запустить все тесты; исправлять только воспроизводимые ошибки.
2. Зафиксировать целевой scope первого релиза: минимальный 2D runtime, проект/сцена/ресурсы, input, physics contract, визуализация, редактор или явно отдельные этапы.
3. Довести базовые системы и сериализацию с тестами и форматными миграциями.
4. Реализовать реальный runtime/rendering и редакторский play mode; выбрать аудио backend; интегрировать TileMap/particles/animation.
5. Определить scripting API и sandbox после стабилизации runtime, затем экспортировать и запускать game executable на Windows/Linux.
6. Провести CI, чистые release builds, тесты пакетов, обратную совместимость, документацию и только после критериев приёмки объявлять v1.0.

## Исполняемый файл

В проекте настроена цель `gridengine_demo` (не отдельная GUI-игра). В этой проверке получить EXE не удалось, потому что `cmake` отсутствует в командной среде. Существующие каталоги `build*` не считаются доказательством актуальной успешной сборки; не проверено, содержат ли они рабочие бинарники. После установки/доступности CMake и C++ toolchain выполнить команды из README. Для Visual Studio генератора ожидаемый путь обычно `build\\Release\\gridengine_demo.exe`, но существование файла здесь не подтверждено.
